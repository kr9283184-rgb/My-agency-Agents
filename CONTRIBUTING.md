# Contributing

Thanks for helping improve this project.

## Workflow

1. Create a focused branch from `main`.
2. Keep changes small and document architectural decisions.
3. Add or update tests when implementation is present.
4. Update `README.md` when commands, dependencies, configuration, or architecture change.
5. Open a pull request with a summary and testing notes.

## Quality rules

- Do not commit secrets, credentials, generated databases, local environments, or machine-specific files.
- Prefer deterministic behavior and explicit configuration.
- Keep agent interfaces and orchestration contracts documented.

## Pull requests

Include the motivation, files/components changed, validation performed, and any configuration or migration notes.
